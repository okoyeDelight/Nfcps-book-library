# Tests

## Test 1 - Two members create and join a synchronized Watch Together room [sanity]
Viewport: mobile (375x667)
Covers: Watch Together room creation, /api/watch/rooms routes, realtime WebSocket entity subscription, persisted room state, participant presence, host playback controls, shared reactions and discussion
Description: Verifies the core social Watch workflow works across two members without requiring an account wall.

Steps:
1. Actor A opens a sermon, opens Watch Together, enters "Ada" and creates a room; note the six-character room code
2. Actor B opens NFCPS Watch on another client, opens the shared room code, enters "Chidi" and joins
3. Actor A taps Pause and then Play together, sends a prayer message and a reaction; Actor B sends a chat reply

Expected: Both clients show the same room code and two participants, Actor B receives host playback-state changes through the live room, and the prayer, reaction and reply appear in the shared conversation without manual refresh.

## Test 2 - Ask This Sermon uses captions and timestamp evidence instead of guessing
Viewport: desktop (1280x800)
Covers: /api/watch/sermon/:id/transcript, transcript cache/fallback state, /api/watch/sermon/:id/ask, grounded AI answer, timestamp evidence and player jump
Description: Verifies sermon Q&A is explicitly grounded in readable captions and refuses to invent an answer when a transcript is unavailable.

Steps:
1. Open a trusted sermon and review the Ask This Sermon status
2. If Transcript ready is shown, ask "What practical instruction should I apply?" and open one timestamp evidence item; if captions are unavailable, review the explicit unavailable explanation
3. Return to the sermon player

Expected: A transcript-ready sermon returns a concise answer with timestamp evidence and tapping evidence seeks the player to that moment; a sermon without readable captions shows a clear no-guess explanation rather than generating an unsupported answer.

## Test 3 - Watch Together room permissions and reconnect behavior are safe
Viewport: desktop (1280x800)
Covers: room session token persistence, presence reconnect, host-only playback mutation guardrail, guest leave, host end-room state and 24-hour room lifetime messaging
Description: Verifies room controls remain owned by the host while guests can reconnect and participate safely.

Steps:
1. Actor A creates a Watch Together room and Actor B joins it
2. Actor B refreshes the room page, confirms the saved room session reconnects, then uses Catch up to host
3. Actor B leaves the room; Actor A ends the room

Expected: Actor B reconnects as the same local room member but does not receive host playback controls, leaving removes the guest session from the active room, and ending the room visibly disables synchronized playback and new discussion.

## Test 4 - Deep Watch features do not break Home, Shorts, growth journeys or fallback content
Viewport: mobile (375x667)
Covers: /api/watch/feed, Home infinite feed, Shorts, Subscriptions, Daily Watch, Growth Journeys, Sermon Companion notes and trusted fallback guardrail
Description: Verifies the new deep infrastructure sits around the existing YouTube-style and growth experience without regressing it.

QA Faults:
```json
[
  {
    "method": "GET",
    "path": "/api/watch/feed",
    "status": 500,
    "body_json": { "error": "simulated_watch_outage" }
  }
]
```

Steps:
1. Open NFCPS Watch while the feed request fails and confirm trusted curated fallback videos remain visible
2. Open Shorts, return Home, start a Growth Journey and open its sermon
3. Write a private Sermon Companion note and save a takeaway

Expected: Watch remains usable during the simulated feed outage, YouTube-style navigation and Shorts still work, and Journey/Companion state can still be saved locally.

## Test 5 - Reading remains connected after deep Watch infrastructure
Viewport: mobile (375x667)
Covers: Watch-to-reader bridge, /api/ebooks/catalog, visible e-book shelf, /api/reader/book, in-app reader pagination and saved reading position
Description: Verifies deep Watch work does not regress the connected NFCPS reading experience.

Steps:
