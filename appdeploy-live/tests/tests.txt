# Tests

## Test 1 - NFCPS One opens as a calm app and Read never starts blank [sanity]
Viewport: mobile (375x667)
Covers: mature Home app shell, Home/Read/Watch/Library/You navigation, immediate locally owned e-book shelf, /api/ebooks/catalog enrichment, Read action and /api/reader/book
Description: Verifies the new product shell is concise and the Read screen always has usable books even before or without the external catalogue.

Steps:
1. Open NFCPS One and confirm Home shows the NFCPS One identity, core destinations and no giant physical/e-book sections stacked on the page
2. Tap Read and immediately confirm The Pursuit of God and other starter books are visible; open one with Read
3. Advance one page, close the reader and return to Home

Expected: Home stays concise, Read never renders a blank shelf, the selected book opens in the NFCPS reader, and Home can show Continue Reading after reading activity.

## Test 2 - E-book catalogue failure keeps the owned shelf usable
Viewport: mobile (375x667)
Covers: local e-book fallback guardrail, empty-cache protection, /api/ebooks/catalog failure behavior, Read and Download actions
Description: Verifies a catalogue outage cannot erase books that NFCPS One already knows about.

QA Faults:
```json
[
  {
    "method": "GET",
    "path": "/api/ebooks/catalog",
    "status": 500,
    "body_json": { "error": "simulated_catalog_outage" }
  }
]
```

Steps:
1. Open Read while the catalogue request fails
2. Confirm the starter shelf remains visible and shows an unobtrusive Offline shelf state
3. Open The Pursuit of God with Read

Expected: Visible starter books remain on screen throughout the failure and the in-app reader still opens a known public-domain title.

## Test 3 - Watch Together behaves like a real shared viewing room
Viewport: mobile (375x667)
Covers: /api/watch/rooms create/join/state/message/reaction routes, realtime WebSocket subscription, shareable room invite, dominant synced player, member drawer and chat drawer
Description: Verifies the Netflix-party-style Watch Together flow across two people.

Steps:
1. Actor A opens a sermon, taps Watch together, enters Ada and creates a room, then shares the invite
2. Actor B opens the shared link, enters Chidi and joins; Actor A opens People and Actor B opens Chat
3. Actor A pauses and resumes playback and sends a reaction; Actor B sends a chat reply

Expected: Both actors enter the same dedicated viewing room with the video dominant, both members are visible, host playback changes synchronize through realtime updates, and shared reaction/chat activity appears without manual refresh.

## Test 4 - Physical Library is a destination, not Home clutter
Viewport: mobile (375x667)
Covers: Library destination navigation, /api/circulation/catalog live status, physical book browsing and CirculationAction request flow
Description: Verifies physical borrowing remains fully usable after moving it out of the main Home screen.

Covers: You destination, My Books access, Personal Reading Home, Moments and persistent reader state
Description: Verifies personal tools live in one place instead of being scattered through Home.
