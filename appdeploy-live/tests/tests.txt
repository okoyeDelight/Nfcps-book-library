# Tests

## Test 1 - Living Sanctuary Home flows into editorial Read [sanity]
Viewport: mobile (375x667)
Covers: NFCPS One UI v2 Home composition, bottom navigation, Continue Reading state, editorial Read, immediate starter shelf, /api/ebooks/catalog enrichment, /api/reader/book
Description: Verifies the approved mobile design direction is implemented as a calm content-first Home and light cover-led Read experience while preserving the real reader.

Steps:
1. Open NFCPS One and confirm Home presents one dominant reading focus plus a small For You Today area instead of destination-card clutter
2. Tap Read in the bottom navigation and confirm the screen changes to the light editorial Reading experience with visible book covers
3. Open The Pursuit of God, advance one page, close the reader and return to Home

Expected: Home is atmospheric and content-first, Read is light and cover-led, the book opens in the real NFCPS reader, and the reading activity can become the Home continue state.

## Test 2 - Catalogue outage never empties the new Read experience
Viewport: mobile (375x667)
Covers: local e-book fallback, empty-cache protection, /api/ebooks/catalog failure behavior, Read action
Description: Verifies the redesigned Read page remains useful when the external catalogue fails.

QA Faults:
```json
[
  {
    "method": "GET",
    "path": "/api/ebooks/catalog",
    "status": 500,
    "body_json": { "error": "simulated_catalog_outage" }
  }
]
```

Steps:
1. Open Read while the catalogue request fails
2. Confirm the For You and Christian Classics shelves still contain locally known books and the offline message is visible
3. Open The Pursuit of God

Expected: The light Read screen never becomes blank and a known public-domain title still opens in the reader.

## Test 4 - Watch Together keeps shared viewing and chat in one room
Viewport: mobile (375x667)
Covers: /api/watch/rooms create/join/state/message/reaction routes, realtime WebSocket subscription, remembered display name, synced playback, reactions and chat
Description: Verifies two members can enter the simplified shared viewing experience and communicate without exposed realtime machinery.

Steps:
1. Actor A opens a sermon, taps Watch together, enters Ada if needed, creates a room and shares the invite
2. Actor B opens the shared link, enters Chidi if needed and joins; confirm Chat is the natural room conversation area
3. Actor A changes playback and sends a reaction, then Actor B sends a chat reply

Expected: Both actors remain in the same room, playback changes synchronize, reactions and messages appear without refresh, and the active room does not expose connection status or technical synchronization controls.
